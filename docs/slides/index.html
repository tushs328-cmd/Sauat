02
Идея SAUAT

Карта приключений превращает чтение в короткую проверяемую миссию

История даёт контекст. Ответ требует вывода. Доказательство возвращает ученика к тексту.

Один экран, одна мысль, один следующий шаг.

Без аккаунта, с локальным прогрессом и понятным маршрутом от документа к результату.

SAUATЧитай. Исследуй. Доказывай.
03
Как работает

История → доказательство → ИИ-подсказка

01→

История

Короткие документы с ID и источниками. Сначала ученик читает контекст.

02→

Доказательство

Ответ нужно подтвердить фрагментом. Первая попытка сохраняется отдельно.

03

ИИ-подсказка

Подсказка объясняет стратегию, а не выдаёт готовый ответ.

В диагностике подсказки отключены, чтобы измерять навык чтения и доказательства.

04
Демо

05
ИИ и офлайн

ИИ помогает объяснить ход мысли, офлайн сохраняет маршрут

Локальные правила остаются рабочим fallback.

При наличии локального Ollama приложение может получить структурированную подсказку. Если сети или модели нет, интерфейс использует правила и честно показывает офлайн-состояние.

  • Локальноконтент, прогресс и подсказки по правилам
  • ИИOllama, только для подсказки стратегии
  • ОфлайнService Worker и кэш истории
06
Для учителя

Кабинет отвечает на один практический вопрос: что понял ученик

Экспорт у ученика → импорт здесь.

Кабинет принимает JSON-файлы, удаляет дубликаты и показывает навыки по импортированным событиям.

Главная метрикаДоля диагностических заданий, выполненных верно с первой попытки и без подсказок.

Режим жюри не попадает в главную метрику кабинета.

07
Преимущества перед конкурентами

Чем отличается SAUAT

  • Оффлайн-first и лёгкий клиентнативный HTML/CSS/ES-модули, PWA и IndexedDB без внешнего CDN
  • Доказательство отдельно от ответаученик выбирает и проверяет фрагменты, а не только вариант ответа
  • Диагностика entry / exitвходной и итоговый замер работают без подсказок
  • Учитель видит тип ошибкикабинет показывает факт, слабое доказательство и слишком широкий вывод

Наблюдаемые свойства MVP

Это не рейтинг и не обещание измеренного превосходства: отличия видны в текущем клиентском сценарии и импортированных событиях.

ИИ-инструменты: локальная Ollama, rules fallback, Claude для контента и QA, Playwright для браузерной проверки.

08
Безопасность и приватность

Базовый сценарий не требует аккаунта и внешнего профиля ученика

Прогресс хранится на устройстве ученика. Учитель получает только экспортированный файл.

События анонимны: в данных нет имени ученика, только технический анонимный идентификатор.

Импорт проверяет схему и дубликаты. Режим жюри отделяет демонстрационные события от главной метрики.

Это описание текущего MVP, а не обещание полной школьной системы управления данными.
