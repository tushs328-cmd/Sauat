# AI Card

## Модель и режимы

- По умолчанию: без ИИ, встроенный банк и правила подсказок.
- Опционально: локальная Ollama, модель `qwen2.5:1.5b`, URL через `OLLAMA_URL`, имя через `OLLAMA_MODEL`.
- Внешние облачные API не используются. Тексты ученика не отправляются в интернет.

Для SAUAT-контракта `/api/mentor` модель получает только `storyId`, `taskId`, `skill`, язык, числовой `errorProfile` и allowlist ID подсказок/следующих заданий. Ответ запрашивается по JSON Schema и принимается только при точном совпадении с allowlist; невалидный JSON, запрещённый ID, таймаут или лимит переводят запрос в `source: "rules"`. Этот адаптер не получает тексты документов и не генерирует текст на казахском.

Уровень подсказки выбирается детерминированно: `min(lastHintLevel + 1, 3)`. Модель не может перескочить на уровень 3, выбрать стратегию вне текущего уровня или пропустить следующее задание. В prompt передаются четыре few-shot примера профилей ошибок и явные правила: ошибка ответа → `locate`, ошибка доказательства → `compare`/`check_contradiction`, обе ошибки → повторная попытка с растущим уровнем.

При старте сервера локальная Ollama один раз прогревается пустым запросом. `/api/health` сообщает `ai: "available"` только после успешного прогрева; до этого и после ошибки прогрева — `fallback`. Команда `npm run eval:persona` сравнивает 10 профилей с базовым правилом и сохраняет таблицу в `eval/persona/results.md`.

## Назначение

Модель может сформулировать подсказку 2–3 уровня. Она получает только вопрос, варианты, одну цитату и инструкцию не называть правильный вариант. Ответ проходит защитную проверку: если текст содержит правильный вариант или формулировку «правильный ответ», приложение использует офлайн-подсказку.

## Известные ограничения

Модель может ошибиться, говорить слишком общо, не распознать казахскую формулировку или не сослаться на нужное слово. Поэтому UI всегда показывает цитату, а оценка ответа выполняется правилом по индексу варианта. Для свободных ответов и семантической проверки в текущей версии нет безопасного общего оценщика.

## Оценка

`eval/cases.json` содержит 20 фиксированных пар «вопрос → источник». Команда `npm run eval:ai` считает кейс пройденным только если доступная модель вернула подсказку, содержащую опору на источник. Для выбора стратегии используется отдельный `eval/persona/` с 10 профилями; его вывод не подменяет факт живого запуска модели.

Живой прогон `qwen2.5:1.5b` на CPU через локальную Ollama дал 7/10 ответов `source:ai` и 8/10 совпадений с базовым правилом. В двух профилях с ошибкой ответа модель выбрала допустимый `compare`, а правило — более точный `locate`; поэтому модель пока не доказывает надёжную персонализацию стратегии. Реальная польза адаптера сейчас — структурированный allowlist-ответ, ограничение уровня и следующего задания, прогрев/честный health-status и безопасный fallback; выбор стратегии остаётся под контролем правил.

## Вывод для публичной сборки

Живой ИИ работает только локально: сервер должен иметь доступ к Ollama по `OLLAMA_URL`, а модель заранее загружена на этой машине. Публичная статическая версия не отправляет запросы к Ollama и работает на встроенных правилах наставника; при отсутствии сервера это единственный доступный режим. Поэтому `source:ai` нельзя обещать жюри в опубликованном `dist`: там проверяемы только правила, локальные данные, офлайн-кэш и экспорт событий.
