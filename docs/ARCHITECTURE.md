# Архитектура

## Поток данных

```text
Browser/PWA
  ├─ /api/auth/*                 локальная сессия в памяти
  ├─ /api/student/*              ответы, наставник, прогресс
  ├─ /api/teacher/*              TXT/PDF → черновики → публикация → аналитика
  └─ /api/admin/*                backup/restore и сводка
          │
          └─ data/saulat.json    локальное JSON-хранилище
                  │
                  ├─ taskBank.js (60 встроенных заданий)
                  └─ ai.js → Ollama внутри Docker (опционально)
```

`src/server.js` создаёт Express-приложение и проверяет роль на каждом защищённом маршруте. `src/auth.js` выдаёт короткоживущую для процесса сессию по коду роли/класса; секреты и пароли не нужны. `src/storage.js` атомарно заменяет JSON-файл через временный файл.

Публичный `taskBank` никогда не содержит `answer` и `explanation`: `publicTask` убирает эти поля перед выдачей браузеру. Свободные материалы учителя хранятся в `draftTasks`, а при публикации становятся частью задания класса. Ответ ученика записывается с `studentKey = classId + name`, поэтому запрос прогресса всегда фильтруется по текущей сессии.

## Офлайн и модель

Без `OLLAMA_URL` приложение не делает внешних запросов. Банк работает полностью локально. В Compose приложение подключается к Ollama по внутренней сети `saulat_internal`; порт 11434 наружу не публикуется. `src/ai.js` использует тайм-аут, просит только подсказку с цитатой и отклоняет ответ модели, если тот совпадает с правильным вариантом или выглядит как готовый ответ.

## Границы MVP

Это локальный пилотный продукт, а не облачная школа: нет внешней авторизации, облачной синхронизации, OCR и продакшен-многопользовательского хранилища. Всё, чего нет в коде или тестах, остаётся гипотезой/следующим шагом.
