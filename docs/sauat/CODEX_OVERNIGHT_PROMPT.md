## ЖЁСТКИЕ ГРАНИЦЫ
- Пиши ТОЛЬКО в: `qa/**`, `content_drafts/**`, `docs/sauat/reports/**`, `docs/demo/**`, `tools/qa/**`, `tools/demo/**`. Нельзя менять `public/**`, `src/**`, `test/**`, `content/*.json`, `package.json`, `Dockerfile`, `docs/sauat/CONTRACT.md`, `TASKS.md`, `schema.json`. Найденные дефекты оформляй файлами `qa/bugs/BUG-NNN.md` (шаги, ожидалось, получилось, серьёзность P0–P3, скриншот), а не правкой чужих файлов.
- Запуск приложения только из КОПИИ репозитория (скопируй в `qa/.tmp/app/` без `.git`, `node_modules` можно скопировать), порт 3400, `INCLUDE_DRAFT=1`; в рабочей папке `data/` ничего не пиши.
- Коммить только свои пути: `git add qa content_drafts docs/sauat/reports docs/demo tools/qa tools/demo` затем `git commit`. Без `git add -A`, без `stash`, без `reset --hard`, без push, без force.
- Сеть: разрешено только читать открытые страницы источников (HTTP GET). Ничего не отправлять, не создавать аккаунты, не вводить пароли и ключи, не скачивать исполняемые файлы. Секреты не печатать и не сохранять.
- Не выдумывай факты, цифры, цитаты, пользователей, школы и результаты пилота. Что не проверено, помечай «ПРОВЕРИТЬ». Результаты симуляции учеников — это синтетические данные и всегда маркируются «СИМУЛЯЦИЯ».

## ВОРКСТРИМЫ

### W1. QA-агенты «ученики» (Playwright, `qa/`)
Сделай `qa/run.js` и прогоняй полные сценарии по всем историям и диагностике на RU и KK, в трёх вьюпортах (360×800, 768×1024, 1440×900). Персоны: 1) внимательный (все верно с первой попытки), 2) случайный кликер, 3) всегда первый вариант, 4) «подсказкоед» (жмёт все подсказки), 5) офлайн посреди истории (`context.setOffline(true)` после загрузки, перезагрузка, продолжение), 6) переключатель языка посреди задания, 7) двойной клик и быстрые клики (дубли XP? дубли событий?), 8) закрыл вкладку и вернулся (сохранение прогресса), 9) после диагностики: экспорт → импорт в кабинет учителя, сверка чисел с ожидаемыми. Проверки: нет горизонтальной прокрутки, цели нажатия ≥ 44 px, фокус виден, нет ошибок в консоли, XP один раз, первая попытка не перезаписывается, подсказки скрыты в диагностике, RU/KK без пустых строк, «на проверке» только у непроверенных языков, картинки загружаются. Итог: `qa/out/results.json`, скриншоты, `docs/sauat/reports/QA_NIGHT.md` (таблица тест × вьюпорт × язык × PASS/FAIL, список багов с ID).

### W2. Генерация новых заданий и историй (`content_drafts/`)
Не клади в `content/`. Для каждой существующей истории предложи по 4 дополнительных задания (разные типы find/infer_evidence/claim_check), чтобы можно было менять варианты; плюс 2 идеи новых историй P1 (напр. Таңбалы/петроглифы и ещё одна) с проверенными источниками и черновиком JSON по схеме. Формат строго по `schema.json`, оба языка, `reviewStatus` draft, `isFictional` для вымышленных документов. Каждый файл `content_drafts/<id>.json` + `content_drafts/<id>.FACTS.md` (утверждение → URL → точная фраза-опора). Проверяй схему: `node src/content-validator.js` с путём к черновикам (если валидатор принимает каталог), иначе свой скрипт на Ajv из `tools/qa/`.

### W3. Фактчек всех историй (`docs/sauat/reports/FACTS_*.md`)
Для каждого сегмента case_001…003 открой источник и дай точную фразу-опору. Ищи НОВЕЕ: научные работы и официальные сообщения 2025–2026, которые могли изменить вывод. Особое внимание: case_002 e9 (спутниковые данные cawater, PDF: если не читается, найди другой способ или отметь «НЕ ПРОВЕРЕНО»), даты, числа, названия. Результат: таблица совпало / расхождение / не удалось проверить; расхождения оформи как `qa/bugs/BUG-*.md` с P0/P1.

### W4. Казахский и паритет RU/KK (`tools/qa/kk_lint.js`)
Скрипт: словарь терминов (қорым, қорған, қабір, жәдігер, дереккөз, үзінді, ЖИ), поиск калек и русских слов в kk-строках, проверка, что числа, даты и ID совпадают в RU и KK, отношение длин строк (подозрительные расхождения), одинаковое число вариантов. Отчёт `docs/sauat/reports/KK_LINT.md` со списком «ПРОВЕРИТЬ ЧЕЛОВЕКОМ» по строкам (id → причина). Не переписывай казахский сам в чужих файлах.

### W5. Доступность и производительность (`qa/a11y/`)
axe-core через Playwright по основным экранам; Lighthouse (если доступен) на мобильном профиле; размер загрузки, число запросов, время до интерактивности на «медленной сети». Отчёт `docs/sauat/reports/A11Y_PERF.md` с конкретными селекторами проблем.

### W6. Автозапись демо-видео (`tools/demo/`)
Скрипт Playwright записывает 3-минутное демо (1280×720) по сценарию: хук → документы → задание с ошибкой доказательства → подсказка → ответ → выключаем сеть → новая история работает → диагностика → кабинет учителя. Субтитры на русском вставляй через наложение (как раньше в проекте записывали видео). Выход `docs/demo/demo.webm` (+ mp4 через ffmpeg, если установлен), файлы не коммить, если больше 20 МБ (добавь в .gitignore `docs/demo/*.mp4|webm`), коммить скрипт и `docs/demo/README.md`. Данные в демо реальные из приложения, без выдуманных результатов.

### W7. Материалы для сдачи (`docs/sauat/reports/SUBMISSION_KIT.md`)
Собери из фактов проекта (не выдумывай): черновик описания для формы (до 1000 знаков: проблема, для кого, что работает, как проверить), список использованных ИИ-инструментов и библиотек (по `package.json`, `docs/THIRD_PARTY.md` и коммитам; п. 6.3 Положения), 10 слайдов (заголовок и 2–4 пункта, какие скриншоты взять), 10 вопросов жюри с честными ответами, перечень ограничений («не проверено: казахский человеком, пилот на детях, живой ИИ…»).
