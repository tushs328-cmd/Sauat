# SUBMISSION_KIT — черновик, не отправлено

## Текст для формы (до 1000 знаков)

SAUAT «Оқы да дәлелде» — офлайн-ориентированная игровая практика функционального чтения для 7–9 классов. Ученик читает короткие фрагменты, находит ответ, отдельно выбирает доказательство и видит, где вывод не подтверждён текстом. В проекте есть русская и казахская версии истории «Золотой человек», входная диагностика на жизненных текстах, локальные события и экспорт результата. Проверить локально: `npm install`, затем `INCLUDE_DRAFT=1 PORT=3400 npm start`, открыть `http://localhost:3400`, выбрать язык, пройти историю и диагностику, нажать «Экспорт результатов». Автоматические тесты и контентный валидатор проходят. В ночной проверке 12 из 13 синтетических сценариев прошли; офлайн-перезагрузка требует исправления. Это демо метода измерения, а не доказательство пилота на детях.

## Инструменты и библиотеки по репозиторию

- Node.js + Express — локальный сервер и API.
- Ajv — проверка JSON-контента по схеме.
- Multer — загрузка файлов для API.
- pdf-parse — работа с PDF в серверной части.
- Playwright CLI — синтетические браузерные QA-сценарии и скриншоты.
- Опциональная локальная Ollama (`qwen2.5:1.5b`) — структурированный ответ наставника; при недоступности работает rules fallback.
- Источники и референсы перечислены в `docs/sauat/SOURCES.md` и `docs/THIRD_PARTY.md`; лицензии ассетов перед публикацией требуют отдельной проверки.

## Вопросы жюри и честные ответы

1. **Это валидированный тест?** Нет. Это демонстрация метода измерения; пилот на детях не проводился.
2. **Что работает сейчас?** История «Золотой человек», входная диагностика, RU/KK интерфейс, локальные события и экспорт.
3. **Работает ли офлайн после перезагрузки?** Сейчас нет: BUG-001 воспроизведён в ночном прогоне.
4. **Почему только одна история открыта?** Арал и Байконур видны в банке, но в UI помечены «Скоро откроется»; это BUG-003.
5. **Что делает ИИ?** Опционально выбирает разрешённую стратегию/подсказку; правила остаются fallback и модель не создаёт факты.
6. **Уходят ли ответы учеников в облако?** В штатном режиме нет; события хранятся локально и экспортируются пользователем.
7. **Можно ли доверять казахскому тексту?** Пока нет: оба языка имеют `draft` и требуют проверки человеком; KK lint нашёл места для ревью.
8. **Как учитель получает данные?** В текущем follow-up UI есть кабинет и импорт JSON; полный export → import → сверка чисел после параллельных изменений ещё не подтверждены отдельным W1-прогоном.
9. **Какие тесты есть?** `npm test` — 56/56, `npm run validate` — exit 0, браузерный W1 — 12/13.
10. **Что сделаете первым после хакатона?** Исправим offline lifecycle, затем teacher import, доступность целей и откроем подтверждённые истории.

## Ограничения и не проверено

- Человеческая проверка KK не выполнена; автоматический lint не оценивает литературность.
- Пилот на детях, retention и образовательный эффект не измерялись.
- Живой Ollama в ночном W1 не запускался; проверен только fallback/UI-контракт.
- Полная цепочка teacher import и сверка чисел после параллельных изменений не проверены отдельным W1-прогоном.
- Офлайн-перезагрузка воспроизводимо ломает восстановление приложения.
- Публичная публикация, платный хостинг и отправка формы не выполнялись.
- Скриншоты QA — артефакты синтетической проверки, не результаты пользователей.
