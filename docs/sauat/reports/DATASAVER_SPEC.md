# B26 — контракт режима экономии трафика

Статус: Codex B добавляет контракт и генерацию SW в `scripts/build-static.mjs`;
Codex A реализует обнаружение и UX в `public/**`. Публичные файлы этого контракта
в этой задаче не меняются.

## Сигнал

Клиент включает режим, если `navigator.connection.saveData === true` или
`navigator.connection.effectiveType === "2g"`. Если API браузера отсутствует,
обычный режим сохраняется. Сигнал не является персональными данными и не должен
отправляться на сервер.

## Поведение сборки и Service Worker

- Обычный SW при установке предзагружает shell, manifest, все истории и ассеты.
- В режиме экономии регистрация SW получает query-флаг `saulatSaveData=1`.
  При установке кэшируются только shell, manifest и иконки; истории и ассеты не
  добавляются автоматически.
- После выбора истории клиент передаёт активному SW сообщение:

```js
{ type: 'SAULAT_PRECACHE_STORY', story: { file, assets } }
```

  SW кэширует только `story.file` и перечисленные `assets`. Значения проверяются
  как относительные пути без `..` и внешних URL.
- `prepareOffline(manifest, selectedStory)` использует выбранную историю для
  проверки готовности в этом режиме; проверка всего манифеста не должна снова
  загружать все истории.

## UX слабого телефона

Codex A должен добавить на корневой элемент маркер вроде `data-save-data="1"` и
CSS-правило `@media (prefers-reduced-motion: reduce)`/маркер режима, отключающее
анимации и переходы. Тексты должны объяснять: «Экономия трафика: история
загрузится при открытии».

## Приёмка

1. В обычном режиме smoke видит полный precache и offline-проверки.
2. В режиме экономии в сгенерированном `sw.js` есть `SAVE_DATA`, пустой список
   историй на install и обработчик `SAULAT_PRECACHE_STORY`.
3. До выбора истории кэш не содержит JSON историй; после выбора содержит только
   выбранный JSON и его ассеты.
4. На слабом соединении нет анимаций; функциональность маршрута и экспорт не
   ломаются.
