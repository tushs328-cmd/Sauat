# CODEX CONTENT PROMPT — история / диагностика SAUAT

Ты автор образовательного контента SAUAT «Оқы да дәлелде» (ученики 7–9 классов Казахстана; Órleu Hack 2026, Кейс 3). Читай: `docs/sauat/CONTRACT.md`, `schema.json`, `CONTENT_GUIDE.md`, `SOURCES.md`, образец `content/case_001.json` (версия 3, принята). Ты владеешь ТОЛЬКО одним файлом `content/<твой id>.json`. Другие файлы не меняй. Коммить только свой файл (`git add content/<id>.json`), ветка `dev`, без push, без `git add -A`.

## Уроки с C01 (не повторяй ошибок)
1. Сегмент документа = ТОЛЬКО пересказ источника своими словами, без выводов, оценок, подсказок и «морали». Выводы живут в заданиях, подсказках и объяснениях.
2. ПРОВЕРЬ АКТУАЛЬНОСТЬ. Источник может быть старым: перед включением факта найди в интернете самые свежие данные (особенно научные работы 2024–2026 и официальные сообщения). Если новое исследование противоречит старой странице, не молчи: покажи оба документа и сделай из этого задание «свежее доказательство меняет вывод» (как в C01).
3. Каждый факт из открытой страницы, которую ты реально открыл. Для каждого сегмента `sourceId`; в `sources` точный URL и `accessedAt` сегодняшней даты. Нельзя копировать длинные куски текста. Если факт нельзя подтвердить, не включай.
4. Правильный вариант ответа не должен быть самым длинным; варианты правдоподобны (не абсурдны); RU и KK передают ОДИН смысл (после написания перечитай пары и проверь, что неверный вариант не стал верным в KK).
5. ID сегментов e1…eN подряд без пропусков (лучше не больше 12 сегментов), задания t1…tN, подсказки `tN_h1..h3`. Все ссылки на `eN` в подсказках и объяснениях проверь.
6. `acceptedEvidenceSets`: все допустимые наборы, не слишком большие (обычно 1–3 сегмента).
7. Казахский пиши живым литературным языком, не калькой; термины: қорым, қорған, қабір, жәдігер, дереккөз, үзінді, ЖИ. `reviewStatus`: оба языка `draft`; список строк «ПРОВЕРИТЬ ЧЕЛОВЕКОМ (kk)» верни в отчёте.
8. Изображение: твой SVG делает Codex A; в JSON укажи `image.file` вида `assets/<id>_reconstruction.svg` с `credit`, `license`, `isReconstruction:true` и честным `alt`; сам файл не создавай.
9. Если в документе есть выдуманные/учебные тексты, ставь `isFictional:true`; для авторского текста `sources[].url` = `urn:sauat:original-text`, `title` = «Авторский учебный текст SAUAT» (если валидатор не принимает URN, не меняй схему: опиши проблему в отчёте).
10. Запрещено: выдуманные факты, цифры, цитаты; реальные люди и бренды в вымышленных документах; код проекта Qadam AI.

## Типовая история (practice): 3–5 минут, 1–2 документа, 4 задания: `find`, `infer_evidence`, `claim_check` («поймай ИИ на ошибке», утверждение со скрытой ошибкой, опровергаемой сегментами), плюс ещё одно (`infer_evidence` или `find`), 3 подсказки к каждому, `reward` (раскрытие загадки + карточка артефакта) и `contentVersion: 1`.

## Диагностика (kind: diagnostic)
Два файла: `diag_entry_001.json` (входная) и `diag_exit_001.json` (итоговая): по 3 задания каждый, на НОВЫХ жизненных текстах (расписание, объявление, таблица данных, инструкция без медицинских советов), не про Золотого человека, Арал или Байконур, ВСЕ тексты оригинальные и помечены `isFictional:true`. Навыки в обоих файлах одинаковы по порядку (t1 `find`, t2 `infer`, t3 `evidence`), сложность сопоставима, но тексты и числа разные. `hints: []` (подсказок нет), `explanation` показывать после ответа можно. `reward` минимальный. Это демонстрация метода измерения, не валидированный тест.

## Проверки перед отчётом
`npm run validate` (PASS), `npm test` (должны проходить все, кроме тестов других чатов, если они упали из-за их незаконченной работы; опиши это). Отчёт: что сделано, файл, commit, таблица «утверждение → источник (URL) → точная фраза-опора» (для практики), список «ПРОВЕРИТЬ ЧЕЛОВЕКОМ (kk)», сомнения, что НЕ проверено.
