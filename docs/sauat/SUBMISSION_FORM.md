# Черновик формы hackathon.kz — SAUAT

Этот файл содержит готовые тексты для вставки в форму. Публичные ссылки оставлены
плейсхолдерами: в репозитории нет подтверждённых URL прототипа, кода или слайдов.
В текущем demo-манифесте — 5 practice и 2 diagnostic истории; все семь имеют
`reviewStatus: draft` и доступны в режиме жюри `?jury=1`.

## Короткое описание проекта

SAUAT — офлайн-платформа, которая превращает чтение в расследование: ученик читает
короткую историю, находит подтверждение в источнике, отделяет факт от гипотезы и
получает подсказку по месту ошибки. Учитель видит прогресс по навыкам, а при
доступной локальной Ollama приложение может подключить ИИ-адаптер; без неё работает
проверяемый наставник на правилах.

## Полное описание проекта

SAUAT помогает тренировать функциональную грамотность через интерактивные истории.
Вместо угадывания ответа ученик должен связать утверждение с фрагментом источника,
объяснить вывод и заметить противоречие. Контент хранится в JSON и проходит схему и
кросс-проверки валидатора. В клиенте есть карта истории, задания, уровни подсказок,
диагностические входная и итоговая истории, локальный прогресс и экспорт событий.

Приложение можно собрать как статический PWA-пакет: Service Worker кэширует оболочку,
манифест, истории и ассеты, а rules-наставник работает без сервера. Серверная часть
на Express добавляет роли, импорт материала, сводку учителя и опциональный адаптер
к локальной Ollama. Модель получает ограниченный профиль ошибки и возвращает только
разрешённые идентификаторы; при недоступности или некорректном ответе используется
правило.

## Проблема

При чтении учебного или бытового текста недостаточно выбрать ответ: важно понимать,
какой фрагмент его подтверждает и где заканчивается факт и начинается интерпретация.
Обычная викторина плохо показывает эту ошибку ученику и не даёт учителю прозрачного
сигнала, какой навык нужно повторить.

## Решение

- интерактивная история с документами, утверждениями и доказательствами;
- отдельная проверка ответа и выбранного доказательства;
- подсказки, которые растут по уровню и не раскрывают готовый ответ;
- диагностические истории до и после практики;
- локальная работа, кэш и экспорт событий для нестабильного интернета;
- правила как надёжная основа и локальный ИИ-адаптер как опциональное расширение.

## Текущий состав demo

Свежая статическая сборка содержит **7 историй: 5 practice** (`case_001`–
`case_005`) и **2 diagnostic** (`diag_entry_001`, `diag_exit_001`). Для каждой
истории в манифесте сохранён `reviewStatus: draft` для RU и KK; плашка о проверке
казахского остаётся видимой. Параметр `?jury=1` открывает все семь историй для
показа. Это состав прототипа, а не заявление о проведённом пилоте или готовности
контента к массовой публикации.

## Технологии

- статический PWA на HTML, CSS и JavaScript;
- Service Worker, localStorage и JSON-контент;
- Node.js и Express для API;
- JSON Schema и Ajv для валидации контента;
- Multer для загрузки файлов и pdf-parse для PDF с текстовым слоем;
- Ollama с `qwen2.5:1.5b` только в локальном серверном режиме;
- Playwright CLI для браузерных QA/demo-сценариев; он не является runtime-зависимостью
  `package.json`.

## Польза и масштаб

Польза для ученика — видимая связь между ответом, источником и ошибкой. Польза для
учителя — материал, диагностическая пара и сводка по навыкам без необходимости
отправлять ученические тексты во внешний ИИ-сервис. Масштабируемость заложена в
формате историй: новую тему можно добавить отдельным JSON-файлом после проверки
источников, переводов и ассетов. Сейчас это прототип, а не доказанный массовый
сервис: публичное использование, нагрузка и качество всех переводов отдельно не
валидированы.

По свежей `build:demo`-сборке `npm run size` показывает **72.8 KB gzip** для
стартового набора (262.2 KB raw), при лимите 1.5 MB gzip. Формулировка для формы:
«Работает на слабом интернете: первая загрузка около 72.8 KB gzip по измерению
сборки, дальше маршрут доступен офлайн после установки Service Worker». Это
оценка файловой gzip-суммы, а не обещание скорости конкретной сети; первый запуск
требует соединения, а режим экономии трафика подгружает выбранную историю по мере
открытия.

## Пилот: план

**Планируется**, но результаты ещё не собраны. Для мини-пилота предусмотрены
20–30 учеников 7–9 классов и два урока по 25 минут: входная диагностика,
три практические истории, затем итоговая диагностика. События будут анонимными,
без имён и контактов; до начала нужны согласия родителей/законных представителей
и учителя.

Главная метрика проекта считается только для диагностических событий и отдельно
для entry/exit:

```text
firstTry && answerCorrect && evidenceCorrect && hintsUsed==0
```

План, согласие, инструкция учителю и пустой шаблон результатов находятся в
`docs/pilot/`. Пилот не заявляется как проведённый, а его будущие данные не
выдаются за доказательство образовательного эффекта.

## ИИ в проекте

Ollama с моделью `qwen2.5:1.5b` — только локальный опциональный адаптер. Он
получает безопасный профиль ошибки и выбирает структурированную стратегию из
allowlist; тексты ученика и исходные документы ему не передаются. Правила всегда
контролируют уровень подсказки, следующий шаг и fallback при таймауте, ошибке
схемы или недоступной модели. В публичном `dist` запросов к Ollama нет — работает
rules-наставник.

Персонализация проверялась на 10 профилях в `npm run eval:persona`: сохранённый
живой прогон дал `source:ai` в 7/10 случаев и 8/10 совпадений с базовым правилом.
Это не доказывает, что модель лучше правил: в двух профилях с ошибкой ответа она
выбрала `compare`, тогда как правило выбрало `locate`. Подробности и ограничения:
`docs/sauat/AI_CARD_RU.md`.

## Использованные ИИ-инструменты и библиотеки

### Инструменты разработки

- **Codex** — backend, валидатор контента, manifest/static build, rules/AI-адаптер,
  API-тесты и security-проверки.
- **ChatGPT** — подготовка черновиков историй и работа с формулировками контента;
  факты должны проходить человеческую проверку по источникам.
- **Claude** — контракт, архитектурное ревью, интеграционные проверки и QA-обратная
  связь.
- **Ollama + `qwen2.5:1.5b`** — опциональный ИИ-наставник внутри продукта при
  локально доступной модели. В публичном статическом `dist` используются правила,
  не удалённый ИИ.

### Библиотеки и инструменты проекта

Фактические runtime-зависимости сверены с `package.json`: **Express**, **Ajv**,
**Multer** и **pdf-parse**. **Playwright CLI** используется для браузерных QA/demo
сценариев через существующий tooling, но не записан в runtime-зависимости проекта.
Кандидаты из `SOURCES.md` вроде Vite PWA, Dexie и Lucide не выдаются за
использованные библиотеки.

## Честные ограничения

- живой ИИ работает только локально через Ollama; публичная статика использует
  rules-наставника;
- результат модели ограничен allowlist и может быть заменён rules fallback;
- истории и переводы, которые имеют статус `draft`, требуют человеческой проверки;
- demo-сценарий синтетический и не представляет реальных учеников;
- статическая сборка требует первого открытия по сети для установки Service Worker;
  локальный smoke и браузерная проверка подтверждают offline-маршрут, но публичный
  hosting URL ещё не проверен;
- размер стартового набора измерен как 72.8 KB gzip; это оценка сборки, а не
  замер скорости конкретного слабого соединения;
- все 5 practice и 2 diagnostic открыты только в demo-режиме, а их `draft`-статус
  нельзя выдавать за завершённую редакторскую и казахскую проверку;
- ссылки Science.org и UNESCO из контента при проверке обычным `curl` вернули 403;
  это не объявляется битой ссылкой, но требует отдельной проверки доступности;
- нагрузочные показатели, массовое использование и образовательный эффект не
  подтверждены полевым исследованием.
