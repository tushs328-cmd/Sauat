# Как добавить историю за 30 минут

Этот короткий маршрут предназначен автору или учителю, который добавляет одну
учебную историю в SAUAT. История хранится в одном JSON-файле
`content/<id>.json`. Учебный пример с тремя сегментами и тремя типами заданий
находится в [examples/story_example.json](examples/story_example.json).

## 0–5 минут: выбрать ситуацию и каркас

1. Возьмите один короткий текст, который можно понять без внешних знаний:
   объявление, расписание, инструкция, письмо или таблицу.
2. Придумайте стабильный `id` в нижнем регистре: только `a-z`, цифры и `_`,
   например `library_notice_01`. Имя файла должно быть `<id>.json`.
3. Начните с:

   ```json
   {
     "schemaVersion": 1,
     "contentVersion": 1,
     "id": "library_notice_01",
     "kind": "practice",
     "reviewStatus": {"kk": "draft", "ru": "draft"}
   }
   ```

   `schemaVersion` описывает структуру, а `contentVersion` — версию содержимого.
   При содержательной правке увеличивайте последнее. Статус каждого языка
   остаётся `draft`, пока текст не проверил человек.

## 5–12 минут: написать документы и сегменты

Добавьте `title`, `hook` и `documents`. Все пользовательские тексты имеют пару
`{ "kk": "...", "ru": "..." }`: заголовок, хук, название документа, каждый
`text`, вопрос, варианты, подсказки, объяснение и награда.

Для первой истории достаточно одного документа `d1` и трёх коротких сегментов
`e1`, `e2`, `e3`. Один сегмент — одна мысль. ID сегментов уникальны во всей
истории и идут последовательно. Каждое утверждение, претендующее на внешний
факт, должно иметь `sourceId`, совпадающий с `sources[].id`.

Если текст полностью придуман для упражнения, поставьте на документе
`"isFictional": true`. Это честно сообщает ученику, что объявление — учебная
ситуация, а не реальный документ. В таком тексте не приписывайте выдуманные
сведения школе, ведомству или исследованию. Источник в примере — авторская
учебная заметка на зарезервированном домене, а не доказательство реального
факта.

## 12–22 минуты: сделать три задания

Используйте задания одного движка в таком минимальном наборе:

1. `find` — найти прямо сказанный фрагмент. Вопрос должен иметь ответ в одном
   сегменте.
2. `infer_evidence` — сделать вывод и выбрать сегмент или набор сегментов,
   который его подтверждает.
3. `claim_check` — проверить утверждение ИИ. Обязательно добавьте
   `claim.text` на двух языках и `claim.isTrue: true|false`.

Каждое задание содержит `skill` (`find`, `infer` или `evidence`), двуязычный
`question`, минимум три осмысленных `options`, `correctOptionIds`,
`requireEvidence`, `acceptedEvidenceSets` и двуязычный `explanation`.
Для `infer_evidence` и `claim_check` поставьте `requireEvidence: true`. Для
`find` тоже полезно требовать доказательство, чтобы учебный пример показывал
разницу между угадыванием и ссылкой на текст.

`acceptedEvidenceSets` — это список точных допустимых наборов ID, например:

```json
"acceptedEvidenceSets": [["e2"], ["e1", "e3"]]
```

Набор ученика должен в точности совпасть с одним из разрешённых наборов.
Добавляйте альтернативный набор только тогда, когда он действительно
достаточен и не меняет смысл ответа.

## 22–26 минут: написать подсказки и источники

Для тренировочного задания можно дать до трёх подсказок, по одной каждого
уровня:

- `level: 1`, `strategy: "locate"` — куда смотреть: назовите тему или ID
  сегмента, но не ответ;
- `level: 2`, `strategy: "locate"` или `"compare"` — задайте наводящий
  вопрос, заставляющий сопоставить текст и варианты;
- `level: 3`, `strategy: "compare"` или `"check_contradiction"` — разберите
  способ проверки без готового варианта и без подмены решения ученика.

Не повторяйте уровни. Не кладите подсказки в историю `kind: "diagnostic"`:
диагностика считается по первой попытке без подсказок.

Источники имеют обязательные `id`, `title`, `url` и `accessedAt`. Для реального
содержания указывайте точный первичный URL и дату обращения; не добавляйте факт
только потому, что он «кажется известным». Для вымышленного документа явно
оставляйте `isFictional: true` и не маскируйте авторскую заготовку под внешний
источник. Перед публикацией source URL и соответствие сегментов проверяет
человек.

Казахский текст нельзя считать готовым по результату автоперевода. До проверки
носителем оставляйте `reviewStatus.kk: "draft"`; то же правило действует для
русского. В `approved` перевод можно переводить только после человеческой
проверки языка и смысла.

## 26–28 минут: проверить JSON и контент

Из корня проекта выполните:

```powershell
npm run validate
```

Команда проверяет схему, обязательные поля, дубли ID, ссылки `sourceId`,
`correctOptionIds`, `acceptedEvidenceSets`, наличие `claim` и требование
`requireEvidence`. Строка `Контент валиден.` означает ноль ошибок. `WARNING`
не блокирует exit code, но это сигнал автора: исправьте пропуски нумерации,
неравные переводы, слишком очевидную длину правильного варианта или битую
ссылку в подсказке/объяснении.

Читайте диагностику слева направо:

```text
ERROR <файл><путь JSON>: <что нарушено>. Подсказка: <как исправить>
```

Например, `/tasks/1/acceptedEvidenceSets/0` означает второе задание и первый
набор доказательств; `/documents/0/segments/2/sourceId` — третий сегмент первого
документа. Исправляйте именно ID или поле, на которое указывает путь, затем
запускайте валидатор снова. Не удаляйте задание или тест только ради зелёного
вывода.

## 28–30 минут: собрать demo и увидеть историю на карте

Draft-истории намеренно не входят в production-манифест. Чтобы посмотреть
непроверенную историю локально, соберите demo:

```powershell
npm run build:demo
python -m http.server 4173 --directory dist
```

Откройте `http://127.0.0.1:4173/?jury=1`. Сборка с `--include-draft` должна
создать `dist/content/example_story.json`, а
`dist/content/manifest.json` должен содержать запись с `id: "example_story"`.
Именно манифест загружает истории на карту; файл в `content/` сам по себе не
добавляется в интерфейс вручную. В обычной production-сборке draft-история не
показывается, пока оба языка не имеют статус `approved`. После проверки
человеком повторите `npm run validate`, затем соберите обычный пакет и проверьте
манифест ещё раз.

## Что это доказывает и что нет

Этот пример доказывает, что структура истории масштабируется: автор может
добавить новый учебный сценарий одним JSON-файлом, а валидатор проверит его
контракт, ссылки на сегменты и доказательства. Demo-сборка сама подхватит файл
через манифест и покажет историю на карте.

Это не доказывает качество содержания, корректность казахского, пригодность
источников или педагогическую валидность задания. Эти свойства требуют
человеческой проверки: источников — редактором/учителем, казахского — носителем,
а статуса `approved` — после проверки обоих языков. Вымышленный текст остаётся
вымышленным и должен быть так помечен.
