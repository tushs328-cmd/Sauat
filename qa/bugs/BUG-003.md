# BUG-003 — последовательная блокировка историй 02–05 требует продуктового решения

- Severity: P2
- Status: needs product decision; not a confirmed implementation defect
- Owner: A (`public`, story-unlock behavior)
- Scope: W1, synthetic browser simulation (`СИМУЛЯЦИЯ`)

## Evidence

In normal mode, the map showed five practice stories, but cards 02–05 were locked in all six RU/KK × 360/768/1440 contexts. This is consistent with sequential progression, not with missing content. In jury mode (`?jury=1`), all five practice cards were open in all six contexts and had an `open-story` button.

## Steps

1. Open the app normally, choose a language, and return to the map before completing story 01.
2. Observe cards 02–05 marked as locked.
3. Open `http://localhost:3400/?jury=1`, choose a language, return to the map, and inspect the same cards.

## Expected

The product should clearly define whether normal mode is sequential, and the map copy should make that rule understandable. Jury/demo mode should expose the stories intended for review.

## Actual

Normal mode gates cards 02–05; jury mode exposes all five practice stories. The earlier claim that only two stories existed was stale and is superseded by this evidence.

## Evidence files

- `qa/out/results.json`, six `story-availability-*` scenarios with `mode=jury`, `lockedIds=[]`, `practiceStoriesOpen=5`.
- `qa/out/regression-2026-11-26.json`, `storyAvailability` and `jury`.
- Screenshots: `qa/out/screens/map-ru-360.png` (normal map) and `qa/out/screens/jury-map-ru-360.png` (jury map).

## Decision needed

Either document the normal sequential gate in the learner-facing map, or change the unlock policy in `public/js/main.js` if all stories must be immediately available. QA did not modify `public/`.
